CSA Component Library

Tokens, base styles, and components for building on-brand CSA pages, apps, and prototypes. Every class is prefixed csa- so it never collides with cloudsecurityalliance.org's own CSS.

Rules

RuleWhat it means
Library classes only
Use the library’s own csa- classes, the way these pages use them. No lookalike custom classes.
No CSS that imitates a component
About to style a card, button, badge, hero, tabs, table or form? Check these pages first; it’s almost certainly here.
Surfaces set the colors
Put data-surface="light", data-surface="gradient", data-surface="dark" or data-surface="black" on each section; components inside adjust. data-tone nudges a surface one step. Heroes and CTA bands are always dark and take no data-surface.
State is one attribute
aria-pressed for tags, toggles and the bookmark; aria-selected for actions and tabs; aria-invalid for form fields; aria-current="page" for pagination; data-selected for the segmented toggle.
Styling only, no JavaScript
Interactive components describe their behavior in a BEHAVIOR SPEC comment at the top of their CSS file. Build that, not a different interaction.
Placeholders, not brand assets
Fill logo, icon, illustration and photo slots with obvious placeholders, like a file named PLACEHOLDER-hero.jpg. Choosing real assets is a follow-up step.
Flag anything new
If the library truly doesn’t cover something, build it with its conventions, mark it with <!-- NEW COMPONENT NEEDED: what and why -->, and list it at the end.
Tokens, not raw values
Colors are --{letter}{step}, like --b500, with no semantic aliases. Components already set their own colors; use tokens only in your own layout glue.

## CSA Component Library

Pages in this project are built with the CSA Component Library.
Before writing any markup or CSS, read its style guide and follow it:
https://raw.githubusercontent.com/CloudSecurityAlliance/CSA-Component-Library/main/STYLE.md

- Use only the library's `csa-` classes. Check its showcase before
  writing CSS for anything that looks like a component.
- Use placeholders for logos, icons, illustrations and photos.
- Mark anything the library doesn't cover with
  <!-- NEW COMPONENT NEEDED: what and why --> and list it at the end.
Foundations

Colors

The CSA brand palette: primary colors, the Cloud, AI and Zero Trust sub-palettes, and the extended 7×11 ramp. Use the color tokens in CSS, or the .csa-color-* and .csa-bg-* helper classes in markup. Hex values render live from tokens/colors.css; CMYK and PMS values are print specs from the brand guide.

CSA's primary colors define the core of the brand. Blue and orange work together as complementary colors — balancing trust, stability, and energy. Use consistently for logos, primary actions, and high-visibility moments.

The Cloud palette builds on CSA's core blues to create a sense of clarity, openness, and scale. A range of blue tones introduces depth and flexibility while maintaining a cohesive, digital feel rooted in the core brand. Use for cloud-related products, content, and environments.

The AI palette shifts the visual emphasis to warm tones to express innovation, intelligence, and forward momentum. Yellow Orange and Red Orange act as primary colors, creating a bold, high-energy palette supported by CSA Blue for balance and contrast. Use to highlight AI-driven concepts and experiences.

The Zero Trust palette centers on teal tones to communicate security, control, and reliability. These colors introduce a distinct visual identity while remaining grounded in CSA's core palette for consistency and trust. Use for Zero Trust initiatives and security-focused content.

7 families × 11-step ramps (25–800), named --{letter}{ramp}. Swatches below are generated from the actual CSS custom properties, not hardcoded.

One utility class per color token for text and background. Both use !important so they work as overrides anywhere in the component stack. Same letter+ramp naming as the Extended Palette, e.g. --b300 → .csa-color-b300 and .csa-bg-b300.

Pattern
.csa-color-{token}Sets color — text, icons, and SVG fill/stroke via currentColor
.csa-bg-{token}Sets background-color
Background — .csa-bg-{token}
Text color — .csa-color-{token} (shown on --n800 to make every step readable)

Every class is surface-aware; the Color column lists light and dark values, and the dark mode toggle in the top bar shows the dark ones live.

Four surfaces, light, gradient, dark and black, that set text and card colors for everything inside them. Apply one with the data-surface attribute rather than a class, so it can't collide with the host site's CSS. Each surface carries its own heading and body colors and card treatment.

Surface tones

Neutral and deep

An optional second attribute, data-tone="...", nudges a surface one step without becoming a new surface. A tone only changes the band and card fills — every text color and component rule keyed to data-surface keeps applying unchanged. data-tone="neutral" on a light surface gives an n25 band with white cards. It replaces the older .csa-bg-n25 hook — that class is now only a plain background color helper and no longer adjusts what's inside it. data-tone="deep" on a dark surface drops the band to b800 and lifts cards to b700; progress tracks, toggle tracks, and disabled pagination step up to b700 too, so they don't vanish into the band.

A centered dialog over a dimmed navy backdrop, opened and closed without any script. Use <dialog class="csa-modal" popover>, opened by a button with popovertarget and closed by one with popovertargetaction="hide". Escape and a click outside also close it. It's non-modal, so the page behind stays focusable and scrollable; for a true modal, open the same dialog with showModal() from script, with no style changes.

Hero examples

Six ways to build a page hero with library classes, in light and dark treatments. hero-dark is the standard: badge, kicker, h1, sub and CTA row over a navy diagonal. hero-light has the same parts over a mesh gradient, shown with .csa-hero-pattern, an optional line pattern on the left edge that works on any hero. hero-glass-light and hero-glass-dark set a frosted .csa-card-glass panel over a full-bleed photo. hero-glass-graphic widens the glass panel and overlaps a large graphic on its edge; it works with either -light or -dark, shown here in dark. hero-split-graphic drops the panel: content sits directly on the photo in two columns, with a single logo or graphic centered on the right.

Why now

Enterprise AI is entering a new era of failure — from two directions

Data loss, destructive automation, and failed recovery will rise sharply as AI agents spread, and there are no fool-proof preventions in sight. Resilience is what lets an organization take the hit and keep operating.

Direction 1: Adversarial

The agentic surface is under attack

Attackers increasingly target AI agents, model-driven workflows, non-human identities, and automated enterprise systems — turning autonomy itself into an attack surface.

Direction 2: Systemic

Systems fail on their own

Misalignment, excessive permissions, hallucinated reasoning, prompt injection, unsafe tool use, and rushed deployments produce failures with no attacker at all.

Compounding vectors

Nation-state actors using AI-enhanced insider threats, hardware-level vulnerabilities in AI compute, and the commoditization of frontier models through distillation all raise the urgency to build AI resilience now.
